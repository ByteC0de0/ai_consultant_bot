# ИИ-консультант для бизнеса в Telegram

Бот отвечает клиентам компании круглосуточно и мгновенно: цены, адреса, график, доставка, частые вопросы. Отвечает только по вашей базе знаний — обычным текстовым файлам, которые вы правите сами, без программиста. Если ответа в базе нет, бот не выдумывает, а честно говорит об этом и даёт контакт менеджера. Менеджер перестаёт отвечать на одни и те же вопросы, а клиент не ждёт.

Демо-компания — вымышленная кофейня «Зёрна» в Казани (две точки, меню, доставка). База знаний — в папке [knowledge/](knowledge).

**Стек:** Python 3.12 · aiogram 3 · OpenAI-совместимый API (OpenAI, OpenRouter, ProxyAPI, DeepSeek, Ollama) · pydantic-settings · pytest

## Что умеет

- Отвечает на вопросы своими словами по базе знаний компании: меню и цены, адреса и график, доставка, акции, частые вопросы.
- Не выдумывает. Если ответа нет в базе — так и говорит и предлагает написать менеджеру (контакт берётся из базы).
- Не отвлекается: на посторонние темы и попытки «забыть инструкции» вежливо возвращает разговор к компании.
- Помнит последние сообщения диалога: на «а на Чистопольской?» ответит про нужную кофейню. `/reset` — начать заново.
- Сам считает цену: «капучино на овсяном» = напиток + доплата за молоко, с расчётом.
- Если филиалов несколько, отвечает про каждый.
- `/start` — приветствие и кнопки с примерами вопросов.
- База знаний обновляется заменой файлов в папке `knowledge/` — бот замечает изменения сам, перезапуск и правка кода не нужны.
- Модель ИИ меняется в `.env`: облачная (OpenAI, DeepSeek…) или бесплатная локальная (Ollama).

## Пример диалога

Реальные ответы локальной модели qwen2.5:14b (Ollama, RTX 4070) по демо-базе:

> **Клиент:** Сколько стоит капучино на овсяном молоке?\
> **Бот:** Капучино на овсяном молоке будет стоить:\
> • S: 220 ₽ + 60 ₽ = 280 ₽\
> • M: 260 ₽ + 60 ₽ = 320 ₽\
> • L: 300 ₽ + 60 ₽ = 360 ₽
>
> **Клиент:** До скольки вы работаете в субботу?\
> **Бот:** В субботу кофейня «Зёрна» на Баумана работает до 23:00, а на Чистопольской — до 21:00.
>
> **Клиент:** А на Чистопольской есть парковка?\
> **Бот:** На Чистопольской есть бесплатная парковка у входа на 20 минут.
>
> **Клиент:** Сколько стоит аренда зала на вечер?\
> **Бот:** Для аренды зала вечером после 19:00 в кофейне на Баумана стоимость и условия обсуждаются с менеджером. Пожалуйста, свяжитесь с ним для получения подробной информации: Telegram @zerna_manager.
>
> **Клиент:** Какая завтра погода в Казани?\
> **Бот:** Извините, но у меня нет информации о погоде в Казани. Для получения точного прогноза погоды рекомендую обратиться к специализированным сервисам или приложениям.

## Как бот находит ответ

```
вопрос клиента
   │
   ▼
поиск по базе знаний ──► 5 самых подходящих фрагментов + контакты менеджера
   │
   ▼
запрос к ИИ: правила («только по базе, не выдумывай») + фрагменты + последние сообщения диалога
   │
   ▼
ответ без Markdown-мусора ──► Telegram
```

1. Файлы из `knowledge/` (`.md` и `.txt`) режутся на фрагменты по заголовкам. У фрагмента сохраняется путь заголовков («Адреса и график / Кофейня на Чистопольской»), чтобы ИИ понимал, к чему относится текст.
2. На каждый вопрос поиск ([BM25](https://ru.wikipedia.org/wiki/Okapi_BM25) с упрощённым русским стеммингом: «доставка», «доставки», «доставку» — одно слово) выбирает самые подходящие фрагменты. Уточняющий вопрос («а в выходные?») ищется вместе с предыдущим. Векторная БД и отдельные сервисы не нужны.
3. В запрос к ИИ идут только эти фрагменты, а не вся база: дешевле, быстрее и точнее, работает и на больших базах. Файл с контактами менеджера (`KNOWLEDGE_ALWAYS`) подставляется всегда — чтобы бот мог на него сослаться.
4. Ещё в запрос всегда идёт оглавление базы — список всех разделов. На общий вопрос («какой у вас ассортимент?») бот перечисляет то, что реально есть, а не додумывает.
5. Маленькую базу можно отдавать целиком: `KNOWLEDGE_TOP_K=0`.

Посмотреть, какие фрагменты нашлись для вопроса: `python ask.py --context "ваш вопрос"`.

### Как обновить базу знаний

Отредактируйте, добавьте или удалите файлы в `knowledge/`. Формат — обычный текст или Markdown: `#` — раздел, `##` — подраздел. Бот перечитает базу при следующем вопросе.

Советы: пишите факты прямо и подробно — график лучше расписать по дням («суббота: с 9:00 до 23:00»), чем «пн–пт… сб–вс…» или «без выходных»; в начале раздела дайте короткий обзор («Ассортимент: кофе, чай, выпечка…»); один подраздел — одна тема; вопросы из FAQ делайте заголовками.

## Подключение ИИ — только через `.env`

Код не меняется: провайдер выбирается тремя строками в `.env`.

| Провайдер | `LLM_BASE_URL` | `LLM_MODEL` (пример) |
|---|---|---|
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` |
| OpenRouter | `https://openrouter.ai/api/v1` | `openai/gpt-4o-mini` |
| ProxyAPI (оплата из РФ) | `https://api.proxyapi.ru/openai/v1` | `gpt-4o-mini` |
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| Ollama (локально, бесплатно) | `http://localhost:11434/v1` | `qwen2.5:14b` |

`LLM_API_KEY` — ключ провайдера. Для Ollama подойдёт любая непустая строка, например `ollama`.

## Запуск

1. Python 3.12. Создайте окружение и поставьте зависимости:
   ```bash
   python -m venv .venv
   .venv\Scripts\activate          # Linux/macOS: source .venv/bin/activate
   pip install -r requirements.txt
   ```
2. Создайте бота у [@BotFather](https://t.me/BotFather) и получите токен.
3. Скопируйте `.env.example` в `.env` и заполните `BOT_TOKEN`, `LLM_API_KEY`, `LLM_BASE_URL`, `LLM_MODEL`. Остальные настройки описаны в `.env.example`.
4. Запустите:
   ```bash
   python main.py
   ```

Если при старте нет связи с Telegram, бот не падает, а ждёт и повторяет попытку.

### Бесплатно и локально через Ollama

```bash
ollama pull qwen2.5:14b      # ~9 ГБ, нужна видеокарта на 12 ГБ; на слабее — qwen2.5:7b
```

В `.env`: `LLM_BASE_URL=http://localhost:11434/v1`, `LLM_MODEL=qwen2.5:14b`, `LLM_API_KEY=ollama`. На RTX 4070 ответ занимает 1–3 секунды.

Локальная модель на 14B хорошо подходит для демо и закрытого контура, но иногда путает похожие цифры (например, часы работы двух филиалов). Для работы с реальными клиентами лучше облачная модель (gpt-4o-mini, DeepSeek): переключение — три строки в `.env`.

### Проверка без Telegram

```bash
python ask.py "Сколько стоит доставка?" "А в выходные?"   # вопросы подряд, с памятью диалога
python ask.py --context "Где вы находитесь?"               # плюс найденные фрагменты базы
python ask.py                                              # диалог в консоли
```

## Тесты

```bash
pip install -r requirements-dev.txt
pytest
```

65 тестов без сети и без настоящего ИИ: Telegram и модель подменены фейками ([tests/helpers.py](tests/helpers.py)). Проверяются поиск по живой демо-базе (нужный раздел находится, посторонний вопрос — ничего не находит, контакты менеджера всегда в контексте), перечитывание базы при замене файлов, сборка запроса к ИИ, память диалога и `/reset`, сценарии в Telegram (`/start`, кнопки-примеры, длинные ответы, сбой ИИ, слишком длинный вопрос, стикер), настройки `.env`.

## Структура

```
ai_consultant_bot/
├── main.py              # запуск: настройки, база знаний, ИИ, бот
├── ask.py               # вопросы к консультанту из консоли, без Telegram
├── bot/
│   ├── config.py        # настройки из .env (pydantic-settings)
│   ├── knowledge.py     # загрузка базы, нарезка на фрагменты, поиск BM25, автообновление
│   ├── consultant.py    # инструкция для ИИ, сборка запроса, очистка ответа
│   ├── llm.py           # клиент OpenAI-совместимого API
│   ├── history.py       # память последних сообщений диалога
│   └── handlers.py      # Telegram: /start, /reset, вопросы, кнопки-примеры
├── knowledge/           # база знаний демо-кофейни (.md)
├── tests/               # pytest: фейковый Telegram и фейковый ИИ
├── requirements.txt, requirements-dev.txt
└── .env.example         # образец настроек с описанием
```
